# F0 type-enum coverage audit (issue #1349)

Full-fidelity inventory of the `mypy.types` type graph against the
`type_kernel` wire format (`crates/type_kernel/src/wire.rs`). Generated by
hand from `mypy/types.py` at this branch; Phase F0 has no behavior change,
so this document is the artifact, not a benchmark.

Column legend:

- `field`: the `mypy.types` attribute (`__slots__` unless noted).
- `wire`: does the Python wire format serialize it (`Type.write` / class
  `read` in `mypy/types.py`)?
- `enum`: does the Rust `wire::Type` variant carry it?
- `note`: gap disposition. `defaults` = Rust reader fills a constant and
  the writer never emits it (Rust-resident plain data). `live` = holds a
  live Python object; must surface as a stable ID, not copied data.
  `derived` = computed, never serialized.

All wire-carrying classes below share the `Type(Context)` base fields
`line` / `column`: the wire format has no representation for them and
decoded trees read back with `line == -1` (seams whose consumers key on
positions re-stamp from the live input). Likewise the base-class truthiness
cards `_can_be_true` / `_can_be_false` are cached properties, not slots.

## Live-only subclasses (no wire variant, Python-side paths)

These have no `wire::Type` variant and no `Type.write`. They surface at
the Python/Rust seam only via scalar-extraction shims or AST walks, never
as wire bytes.

| class               | fields (slots)                            | why live-only |
| ------------------- | ----------------------------------------- | ------------- |
| `TypeGuardedType`   | `type_guard` (`__slots__`)                | wraps the narrowed item inside `find_isinstance_check`; transient checker state |
| `RequiredType`      | `item`, `required`                        | TypedDict-definition-time only, flattened before checking |
| `ReadOnlyType`      | `item` (attr without `__slots__`)         | TypedDict-definition-time only |
| `CallableArgument`  | `typ`, `name`, `constructor`              | pre-semantic-analysis call argument stub |
| `TypeList`          | `items`                                   | pre-semantic-analysis `[A, B]` list of types |
| `RawExpressionType` | `literal_value`, `base_type_name`, `note` | literal-class container used before `LiteralType` exists |
| `PlaceholderType`   | `fullname`, `args`                        | forward-reference node, requires live symbol table |
| `PartialType`       | `type`, `var`, `value_type`               | live `Var` refs; `type` / `value_type` may be `None` sentinels |
| `EllipsisType`      | (no slots)                                | `Callable[..., X]` ellipsis marker |

## type_ref-style stable-ID fields (live Python object refs)

Per the Phase F0 contract, fields holding live Python object references
must be represented on the wire or across Rust calls as stable IDs, never
as copied graph data. Today's seams use these ID shapes:

| owner class   | field            | ID shape on / across the seam                        | resolved where |
| ------------- | ---------------- | ---------------------------------------------------- | -------------- |
| `Instance`    | `type`           | `type_ref` fullname string on the wire               | `TypeFixer` per-build `_fix_wire_type` |
| `TypeAliasType` | `alias`        | `type_ref` fullname string on the wire               | `_wire_alias_map`, per-build, cleared each build |
| `CallableType`| `definition`     | no wire representation; not modeled in Rust at all   | `expandtype._resync_definitions`, `_restamp_composite_definitions` |
| `UnionType`   | (none)           | plain data, no live refs                            | n/a |
| `TypeVarLikeType` family | n/a   | self-contained wire bytes, identity via `TypeVarId` triple `raw_id`/`meta_level`/`namespace` | fixup key, not a symbol-able ref |
| `PartialType` | `type`, `var`, `value_type` | live only, never crosses (class is live-only) | n/a |

Live-object fields deliberately absent from this list (carried as plain
data instead): `ExtraAttrs.attrs` value objects, `LiteralType.value`
scalars, `UnionType.can_be_*` bools, `TypeOfAny` ints.

## Kernel and seam identity inventory

Where live-object identity is tracked or reconstructed at the seam, with
its disposition:

- (a) **Wire-cache placeholder.** A wire seam's `read_type` can populate
  `instance_cache` with a `NOT_READY` placeholder (`type_ref` set, `.type`
  a `FakeInfo`). `mypy/wirefixup.py:fixup_instance_cache` evicts those
  NOT_READY placeholders, and `TypeChecker.named_type` re-validates every
  cache primitive through `_validated_named_type`, which rebuilds from the
  live `TypeInfo` when the cached entry is absent or still a `FakeInfo`.
  Live-object keyed; consumed by the checker, not by a Rust seam.
- (b) **Native decode caches (identity-free, bytes/type_ref keyed).**
  `_map_supertype_decode_cache` (`maptype.py`), `_narrow_decode_cache`,
  and `_wire_alias_map` are per-build caches keyed by wire bytes or
  `type_ref` string; they never hold a live-object identity across
  builds. The Rust decode side mirrors this with `SeenInstances` keyed on
  `(type_ref, encoded-args)`. Bytes-keyed; no identity jurisdiction.
- (c) **`assuming` recursion guard.** The protocol-impl engine guards
  recursive calls with a thread-local stack: Rust `ASSUMING`
  (`subtypes.rs`, `AssumingPush` RAII) mirrors `subtypes.py`'s
  `assuming_contains` / `pop_on_exit`. Call-scoped, never cross-call;
  the keyed object is the `(left, right)` proper-subtype pair, swept on
  scope exit.
- (d) **Stable-ID mint (`identity.rs`, this issue).** The `handle_for` /
  `handle_for_stable` registry is live-object keyed (raw id and
  weakref-pinned layers) and is the future consumer for seams that need a
  handle stable across calls. Reserved by contract; no production callers
  yet (guarantee 4 in `identity.rs`). The wave30 pair-identity registry
  (unmerged branch `perf/wave30-proto-left`, `fca5e1864`) is not on
  `main`; its design is preserved in the `identity.rs` doc block.

Classification: (a) and (d) are live-object keyed; (b) and (c) are
identity-free or call-scoped and need no registry entry.

## Rust-side invariants for Phase F0

1. The wire format is unchanged in this issue: no `CACHE_VERSION` bump, no
   `mypy/types.py` edits, and Python never sees the new field names.
2. The Rust reader mirrors the `types.py` `read` methods byte for byte;
   plain-data gaps fill from defaults (`UnboundType` false/false, `UnpackType`
   false, `CallableType` `None`, `UnionType` true/`None`/`None`).
3. The Rust writer mirrors `types.py` `write` methods byte for byte and
   never emits the Rust-resident fields; Python always reads back exactly
   what Python wrote (`typeops.py:_serialize_type` and
   `_deserialize_type` contract).
4. `TypeAliasType.is_recursive` crossed the wire as wave31's conditional
   int (#1361): Python's writer emits a tagged LITERAL_INT only when
   `True` and the reader consumes it. Since this scope the kernel's
   `Type::TypeAliasType` variant carries the field, so the Rust round trip
   preserves the flag and the Rust writer re-emits the conditional int
   only when `True`, keeping Python-formatted bytes unchanged. On
   legacy/default-shaped bytes (no tag) the reader fills `false`.
